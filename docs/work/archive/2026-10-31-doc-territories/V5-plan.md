## The slice, decided here
- **Spike in two modes.** User settings set `defaultMode: auto` (`~/.claude/settings.json`). Each probe runs twice, with no permission flag either time. Mode D adds `--setting-sources project,local` in a throwaway repo with no settings, and its `init` `.permissionMode` must read `default`. Mode A runs without that flag, and `init` must read `auto`. A run whose mode reads otherwise is inconclusive. In `-p` nothing can prompt, so a request that would prompt shows as a denial. Each denial is recorded where it appears: in the subagent's `tool_result` (a message with `parent_tool_use_id`), or in the main `result`'s `permission_denials`. The quoted docs tell "prompts in the main session" apart from "auto-denied". If control s3 fails in a mode, s1 and s2 are inconclusive in that mode.
- **Place rule, for both modes.** `git-dir` wins only if, in D and in A: the background `Read` is allowed in the git dir (s2) and in the worktree's git dir (s2w); the main-session writes there are not denied (s4 `Write`, s7 `cp`, with the tool allowed); and the `Read` in `mktemp -d` (s1) is denied in at least one mode. Otherwise, or if any needed run is inconclusive, `mktemp -d` stays, and the spike says so. A worktree's git dir is `<main>/.git/worktrees/<name>`, outside the worktree's working directory. So s2w is required: without it, `git-dir` would carry `mktemp -d`'s exposure in every worktree, and Flow keeps one place, with no branch on the checkout kind. The git dir is named with `git rev-parse --absolute-git-dir`. The spike ends with `Place: mktemp -d` or `Place: git-dir`, then `Decision candidate: <gist>`, which the runner returns as its `Decision candidate:`.
- **Scratch folders.** Every writer makes the session scratch folder at its first step that touches a declared territory, if this session has none: the conductor, `flow:grill` and a manual `/flow:changelog`. Each write gets a fresh, empty folder `mktemp -d "<session scratch folder>/w.XXXXXX"`, so `decisions-check` sees one file.
- **Decision on a territory** (repo layout, `decisions` declared). The § Decisions request plus `scratch: <that folder>`. `flow:docs` writes `<scratch>/YYYY-MM-DD-<slug>.md`, checks the folder, commits nothing, and returns `Composed <absolute path> — check: <summary line>`. Then one adapter invocation sends `op: write; kind: decisions; where: …[; write: …]; name: new; file: <path>`, with `op: none` lines for the other kinds it serves. On `NEEDS:`/`FAILED:`, nothing is handed to the adapter.
- **Status change on a territory.** First `op: read; kind: decisions; name: <id>`, then `decision-status` with `scratch:` and `file: <absolute path of the conductor's copy>`. `flow:docs` copies the file to `<scratch>/<its **Date**>-<name less a leading date>.md`, edits it, and checks it. Any error removes the copy and returns `FAILED: check: <first error>`. Success returns `Composed <absolute path> — <status> — check: <summary line>`, then `op: write; name: <id>; file: <path>`. `superseded_by` takes the new decision's identifier.
- **`list` lines** (contract § Operations): `<identifier> — <field>: <value>; <field>: <value>`, with the § Fields names and list values comma-separated. The conductor puts a returned block in a scratch file and matches `work` anchored: `rg '(— |; )work: <slug>(;|$)' <file> | awk '{print $1}'`.
- **Changelog on a territory.** The close's invocation also sends `op: list; kind: decisions` when `decisions` is on the same adapter, else in its own invocation. The anchored match gives `decision-ids: decisions:<id>, …`. `changelog-write` with `scratch:` inserts the entry into a copy of `excerpts` (or under a new two-line intro) at `<scratch>/CHANGELOG.md`, and writes the version file and commits it alone: `git -C <dir> add <version_file>`, then `git -C <dir> commit -m "Bump the version to vX.Y.Z" -- <version_file>`. It returns `Recorded v<version> — <title> — <sha>; changelog: <absolute path>; missing decisions: …; manual after merge: …`. Then `op: write; kind: changelog; file: <path>`, with no `name`. A territory decision is named `` `decisions:<id>` ``, never linked, since a `file://` link in a repo changelog fails the Gate. With `decision-ids`, the bullet stays even without `decisions-log/`. On a changelog territory, a repo decision is named `` `<root>/decisions-log/<file>` ``.
- **`## Tests` on a territory.** At the profile's § Writing, the two lines go into the conductor's copy of the guidelines `read`: at the start of `## Tests`, or in a new section. Then `op: write; kind: guidelines; file: <copy>`, with no `name`. While `proposed`, the level holds for this session.
- **Returns.** `written`/`written <id>` is reported as `<kind>:<id>`. `proposed <link>` adds the line `- YYYY-MM-DD — <kind>:<name> — <link>` under `## Pending proposals` in `STATUS.md`, a section before `## Log`, created when missing. `<name>` is the id, the composed file's name without `.md` for `new`, or `document` for a single document. Before the append, the conductor runs `git -C <repo root> diff --quiet -- <work dir>/STATUS.md`. If it exits 0, the line is committed alone: `git -C <repo root> add <work dir>/STATUS.md`, then `git -C <repo root> commit -m "Note a pending proposal on <kind>" -- <work dir>/STATUS.md`. Otherwise the line is appended but not committed, and the message says so (it goes with the next `STATUS.md` commit). Outside a work, the link is only reported. The work close's report (Step 6 move 5; § Closing a work step 5) adds `Pending proposals: <kind>:<name> <link>, … | none`.
- **Other contract edits.** In `op: write`, `name` becomes optional: absent, it replaces the single document at `where`. `read` returns repo-form frontmatter: `description` quoted, lists as `[a, b]`, `null` written out. The product block's first line, word for word: ``Context only: cite it as `product:<name>`, never copy its text into the document you write.`` (`<name>` is the read's name, `document` when none).
