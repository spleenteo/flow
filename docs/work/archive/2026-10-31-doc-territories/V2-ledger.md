## Close draft

Narrative: `sources:` in `.flow.yml` lists files that must reach agents, each with a `when` that is a quoted glob or a `{step:}`/`{phase:}` value. Sources matched by path ride in the packet's `## Sources` and are matched again against the planner's `Files:` before the review. Step sources ride in a `## Sources for step: <name>` block after the packet, only for that step's dispatches. The runner gets them as `Execute sources:`/`Close sources:` fields. The skill's example uses the brace form `when: {step: plan}` rather than the plan's `[step: plan]`, by a ruling, and the README copies it. T4's check that printed prompts through `claude -p` was flagged by the safety classifier. It was BLOCKED, and by the user's answer became a routing table: which source files each dispatch carries, in packet or in instruction. All five runs pass. With no `sources:`, V2's Flow and the 57b9c30 baseline route identically. The final review found that an untracked file (a `.env`) could pass the path check and land in the committed packet. Sources must now be tracked by git (`git ls-files --error-unmatch`). The same fix round made headings repo-relative and tightened the field conditions. Four low wording nits remain logged.
Lessons:
- In `claude -p`, a check that asks the model to print the prompts it would build is flagged by the safety classifier (`reasoning_extraction`); ask instead for a routing table of which files each dispatch carries, and grep that.
- A file whose text reaches a committed document (a packet, a ledger) must be tracked by git (`git ls-files --error-unmatch <path>`), or an ignored local secret lands in the repo.
- When the plan's example and the one the first task writes differ, rule on one form at the first review and hand it word for word to every later task that copies it.
