## Close draft

Narrative: `territories:` in `.flow.yml` declares, per kind (`decisions`, `changelog`, `guidelines`, `lenses`, `product`, `archive`), an `adapter` skill of another plugin, a `where` and a `write` word; an undeclared kind stays in the repo. `shared/territories.md` is the contract: declaring, resolution and its stops (malformed entry, missing skill, `unmet`, `unreachable`, never a fallback to the repo), the request lines (one per line, `; `-separated pairs), the adapter skill's sections and the forbidden `context: fork` and `disable-model-invocation: true`, the five ops plus `op: none`, the repo as reference behaviour, and A10's lines on tokens and share links. `/flow:dev` resolves territories after the upgrade check with one `op: none` Skill call per adapter and lists them at opening; flow:docs, the README and the architecture document the key. A throwaway adapter written from the contract alone exposed two gaps the final review fixed: how several requests reach one adapter, and how `write name: new` returns its id. Headless runs proved that another plugin's skill is called by its qualified name: run 1 lists the three territories, run 2 (skill removed) and run 3 (unmet `where`) stop naming the territory, and without the key the opening matches the baseline. The read order did not hold: the model batches `.flow.yml` with the guidelines and changelog in one early shell call, before the adapters resolve, even after a "read only `.flow.yml`" rule was added. By a ruling it is carried to V4, where a guidelines territory makes it matter. V2's low on `step: plan` source conditions is fixed at four places.
Lessons:
- A skill's ordering rule ("read only X until Y") placed in a reference paragraph does not hold headless: the model batches its state reads in one early shell call. Put the rule at the step that hands off (the end of the preceding check), and verify it with a grep of tool-call order, not of the message.
- An adapter or interface written from the contract alone, before any caller uses it, is the cheapest test of the contract: list each point the writer had to guess, and fix those before the final review.
- An order check in a Verified line must name the read as the model actually performs it (`cat`, `Read`, `ls`), not one command (`git show`); a check that finds no match passes vacuously.
