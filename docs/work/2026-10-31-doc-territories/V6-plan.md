## The slice, decided here
- **Request.** `op: archive; kind: archive; where: <where>[; write: <word>]; folder: <absolute path of <root>/work/<dir>>`, with `op: none` lines for the adapter's other kinds. The adapter keeps the folder as one container named `<dir>`, one document per file. Each file is kept as it is (frontmatter included, no fields table), and subfolders become nested containers.
- **Returns and re-run.** `archived <name>` (`<name>` is the container's identifier) or `proposed <link>`. Re-running on an already archived `<dir>` updates the territory copy to the folder as it is now: the adapter replaces it and returns `archived <name>`. Re-running on an open proposal replaces the proposal's content and returns the same `proposed <link>`, never a second one. A proposal stays out of `list` and `search` until accepted. The conductor skips the pending-line append when `STATUS.md` already holds `— archive:<dir> — `.
- **`list` and `search` on `archive`.** One line per container, with identifier `<dir>` and the fields of its `STATUS.md` frontmatter. `list` lines carry `status` and `work` only, with `description` last, an explicit exception to `shared/territories.md:187`. The slug check uses the contract's anchored match, `rg '(— |; )work: <slug>(;|$)' <file> | awk '{print $1}'`. Search hits go into `excerpts:` as `archive:<identifier> — <excerpt>`.
- **Procedure on a territory.** Step 0 is skipped (`archived.md` and `.claude/settings.json` stay untouched). Then, in order: (1) pick the work and run step 2's checks; (2) clean check, `git status --porcelain --ignored -- <root>/work/<dir>` must print nothing, else list its output and ask (`git rm -r` leaves untracked and ignored files behind, and the territory would get files the commit doesn't hold); (3) keep `STATUS.md`'s `## Pending proposals` lines; (4) census, `grep -rn "work/<dir>/" --include="*.md" docs README.md .claude 2>/dev/null | grep -v "^docs/work/<dir>/"`; (5) sibling census, `grep -rn "\.\./<dir>/" --include="*.md" <root>/work | grep -v "^<root>/work/<dir>/"`; (6) `op: archive`; (7) `test -n "<dir>" && test -f <root>/work/<dir>/STATUS.md && grep -qx 'status: closed' <root>/work/<dir>/STATUS.md && git rm -r -q -- <root>/work/<dir>`; (8) rewrite the census lines, after which both censuses without `grep -v` print nothing; (9) `git add <files with updated links>`, then `git commit -m "Archive the <slug> work"`.
- **No `archived:` marker.** The folder is clean, so the territory's copy matches the last commit, and the archive commit carries the date.
- **Inbound text form, word for word.** A Markdown link with text `<text>` and a target under `work/<dir>/` or `../<dir>/` becomes `<text> (archived on <where>: <name>)`. Any other mention of the path becomes `archived on <where>: <name>`. Neither is ever a link, and never the adapter's link. `<where>` is the territory's `where` as written in `.flow.yml`.
- **`proposed <link>`.** Nothing is removed or rewritten. `- YYYY-MM-DD — archive:<dir> — <link>` goes under the work's `## Pending proposals`, unless already there, by the contract's § Writes › The pending line, with the message `Note a pending proposal on archive`. The report says to run `/flow:archive` again once the proposal is accepted. `unmet`, `unreachable` or `FAILED:` is reported and the archive stops, with nothing removed.
- **Resolution in `/flow:archive`.** Whenever `territories:` is declared (any kind), the skill reads the contract and makes the session scratch folder first. Step 2 sends one invocation per adapter: `op: read; kind: changelog` when `changelog` is declared, `op: list; kind: decisions` when `decisions` is, and `op: none` for every other declared kind, `archive` included, so Requires is checked before anything is touched. It stops as the contract's § Resolution says, and nothing is archived on a stop. With no `archive` territory, the rest is § Archive, repo.
- **Anchored step 2.** Changelog: ``rg -n -F -x -e '- **<label>**: `<slug>`' <changelog>``, with `<label>` = `labels.work` (default `Work`). Decisions: `rg -l '^work: <slug>$' <root>/decisions-log/ 2>/dev/null`. On a territory, the first runs on the conductor's copy of the `read`, and the second becomes the anchored `work` match on the `list` block. Checked in throwaway repos: `menu` misses `` `mobile-menu` ``, a custom label matches, `--ignored` prints `!!`, the sibling census finds the link, `test -n ""` exits 1, and `cp -R <src>/. <dst>/` copies the contents.
- **The close's report.** `STATUS.md` leaves the repo, so Step 6 move 5 and § Closing a work step 5 take the pending lines from the archive's report.
