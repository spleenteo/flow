## Close draft

Narrative: The archive goes to an `archive` territory through a new `op: archive` in the contract. The adapter keeps the work folder as a container, the local folder leaves in the archive commit, and inbound links become plain text. The archive's changelog and decisions checks are anchored on the slug. The opening's slug check and memory search also query the archive territory. Writing a test adapter from the contract alone, before any caller existed, surfaced sixteen guesses; ten became contract rules, among them the folder's last path component as `<dir>`, a re-run making the container hold exactly the folder's files, and `search` lines as `<dir> — <excerpt>`. Two fix rounds on T1 went into making a `comment` re-run converge: the match was defined as same files and same contents, and T4 got a step that clears the pending line and commits it alone before the re-run, dropping the `## Pending proposals` heading when it was the only entry, so the accepted container matches the folder. The final review found that the clean check could still send a dirty folder, and that on `proposed` the close merged an un-archived folder. The ruling: the close stops before the merge, and the user re-runs `/flow:archive` on the branch once the proposal is accepted. Left as follow-ups: nothing routes a closed work back to the merge in a later session, and nothing names the merge in the archive report. A pending line cleared before `op: archive` is not restored on `unreachable`/`FAILED:`. `<where>` is quoted verbatim in repo files, so the contract should forbid a token or share id in it. Some prose lows remain (shared/work.md:347, :352; skills/dev/SKILL.md:388; "stays in git history" for project homes). The re-run after an accepted proposal was never run headless. The runner died from an expired login after the final-review fix commit; the resume reviewed 058e305 from its commit, with the executor's report lost.
Lessons:
- A step that clears state before a remote call (a pending line before `op: archive`) says what happens to that state on each failing return: restore it, or name it in the stop's report.
- A stop inside a closing sequence ("the close resumes at the merge") names who resumes it and how a later session finds it; a `status: closed` work is not routed back by the resume table, so the stopping step's report must name the next move.
- A task reviewer bound by "run no tests or builds" won't run `claude plugin validate .` or the link loop even when the instruction asks; the runner runs them itself at the gate.
- An executor's report lives only in the runner until the ledger write; when a runner can die between a commit and that write, the fix commit's subject (or body) lists each finding it meets, so the resume's review has a record to check against.
Decision candidate: on a `proposed` archive the work's close stops before the merge and resumes after the user re-runs `/flow:archive` on the branch; rules out merging with the work folder still in the repo and archiving it later on the default branch.
