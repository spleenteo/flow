## Close draft

Narrative: V5 sends writes through territories. The spike ran headless in two modes. Under `-p`, neither scratch place lets a background reader through in default mode: `mktemp -d` is denied, and so is a linked worktree's git dir, whose `.git` writes are protected paths besides. Auto mode let both through, but only under the documented `-p` exception, so interactive sessions are expected to prompt in both modes. `mktemp -d` stays. The contract gained § Writes, covering decisions, status changes, the close's changelog and the profile's `## Tests`, each composed in a fresh `w.XXXXXX` folder and handed to the adapter, with `written`/`proposed`/`FAILED: <id> exists` returns and the `## Pending proposals` line. The test adapter, written from the contract alone, found twelve gaps. They became contract rules in two fix rounds: the check order, ids for `name: new`, how proposals are seen, `list` field order, read file names, escaping, absolute links. flow:docs takes `scratch:` and `decision-ids:`. The work reference, /flow:dev and /flow:grill call it, and the product block now opens with its "cite, never copy" line inside the block the tool receives. Reviews caught three real path bugs. A decisions-only project lost its changelog entry because `scratch:` went with any territory. Grill passed the session folder, not a fresh one, as `scratch:`. Run 6b showed a free-named copy of a read leaking into the composed file name. Rulings: `git diff --quiet HEAD` replaced the plan's index-only check, and an `ls-files` guard joined it after the final review. The `Pending proposals:` report line appears only with `territories:`. All 13 headless runs passed, every one in `auto` mode. The allowed-tools boundary was never exercised (`sed`, `git switch` ran unlisted), and that stays unverified.
Lessons:
- An adapter written from the contract alone finds the open points only if its writer lists every guess; turn each into a contract rule and re-align the adapter before any caller relies on it.
- A request key that names a folder (`scratch:`) must say which folder at every call site; "that folder" next to a session folder is read as the session folder.
- A composed file name built from "the file's name" inherits whatever name the caller chose; fix the caller's copy name in the contract, or build the name from the identifier.
- `git diff --quiet [HEAD] -- <path>` exits 0 for an untracked or missing file; guard a "commit it alone" step with `git ls-files --error-unmatch <path>`.
- In a user setup with `defaultMode: auto`, headless runs without a mode flag start in `auto` and `--allowedTools` stops binding; a zero-denial check there proves nothing about the allow-list.
- An executor redoing a commit split must re-stage from its edits, never `git checkout --` them; a lost edit then shows up only as a report claim no commit holds.
Decision candidate: The session scratch folder stays a single `mktemp -d` outside the repo, with no branch on checkout kind. The git dir was ruled out: a linked worktree's git dir sits outside its working directory, and `.git` writes are protected paths. Under `-p` neither place lets a background reader through in default mode, and interactive sessions are expected to prompt in both modes (untested).
