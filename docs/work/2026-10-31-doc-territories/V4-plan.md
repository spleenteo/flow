**Mandate**: [V4-packet.md](V4-packet.md) · **Guidelines**: [development-guidelines.md](../../development-guidelines.md) · **Lessons**: [lessons.md](lessons.md) · **Execution rules**: [executor.md](../../../agents/executor.md)

**Summary**
1. T1 adds `## Reads` to `shared/territories.md`: the request each moment sends per kind (`op: none` lines for the rest), descriptions with a `touches` match by `rg`/`awk`, the excerpts file, the scratch folder, sources naming a territory, the product block, the packet's place.

3. T4 routes the opening's reads (profile, draft and Step 0 offers, memory table, Step 1's search); T5a the slice's reads (sources, resume, product, impact, packet, review, gate); T5b the packet's place (moves 3–4, close move 3, the ledger's `Packet:` line, resume rebuild, the runner's headings).

## The slice, decided here
- **Reads, by moment** (T1's table, cited as "the contract's § Reads"): opening, before the profile: `guidelines` → `op: read`; Step 1's memory search: `decisions` and `changelog` → `op: search` with the request's keywords. Resume (standing documents): `decisions` → descriptions, keywords from `STATUS.md`'s `description:`. Impact, slice packet, resume at `step: plan`: `decisions` → descriptions with the slice's files, `lenses` → `op: read`, a matched territory source → `op: read` with `name`. Review: descriptions again with the planner's `Files:`. Opening of `framing-doc` and `shaping`, and the conductor writing `frame.md` itself: `product` → `op: read`. Close, changelog step: `changelog` → `op: read`.
- **One invocation per adapter per step**: every declared kind it serves gets a line, its read or, when the step has no read for that kind, `op: none`, all in the same invocation. A result already in the scratch folder this session is reused (the guidelines at a resume, the `list` result within a slice).
- **Descriptions** = `op: search` (keywords) plus `op: list` (no filter) in one invocation. The `touches` match runs with `rg` or `awk` on the list results file (a block of ten lines or fewer is matched as returned), by `flow:docs` § Op `search` › `files`'s rule; the conductor reads only the matched lines. Kept: the search hits and the matches, one line each, `<kind>:<identifier> — <description>`.
- **Excerpts file**: those lines for `search` and `descriptions`; for the changelog ops, the file the changelog `read` returned. `flow:docs` takes the lines as matches, merges them with the repo's, keeps ten, output unchanged; the changelog ops take tone and language from the excerpts instead of `<changelog>`, and `changelog-write` still writes `<changelog>` (writes are V5). A missing `<changelog>` path is left out of `search`'s `rg` call.
- **Scratch folder and packet place**: one `mktemp -d` per session at the first territory read, reused (the `/flow:design` § Check pattern), never committed. When `territories:` declares `decisions`, `guidelines` or `lenses`, or a matched source names a territory, `V<n>-packet.md` goes there, else in `<work dir>/` as today; the ledger's head gets a third line `Packet: <path>`; close move 3 adds the packet only from the work dir; a resume at execute whose scratch packet is gone rebuilds it in this session's scratch folder, and a `Ruling:` line records the new path.
- **Guidelines on a territory**: `## Tests` and `## Gate` come from its `read`, no branch lookup, no local file; a missing `## Tests` is asked and holds for this session only; the gate at close comes from the packet. § The draft and Step 0 offer no guidelines or lenses file for a declared kind (Step 0 can't run with a configuration file, so its clause is a read-through).
- **Sources naming a territory**: `{territory: <kind>, name: <name>, when: …}` in place of `path`; example, word for word (lesson 7): `sources: [{territory: product, name: voice, when: ["app/**"]}]`. Undeclared kind → skipped and named; no `git ls-files` check; heading `### <kind>:<name>`; to the runner, the scratch path of its `read`.
- **Product**: a block named `` `## Product context` `` (written in backticks in the contract), the `read` text verbatim, right below the criterion, above the path instruction, for `framing-doc` and `shaping` only. On the definition path the frame phase opens with `flow:brainstorm`, which gets no block; the conductor writing `frame.md` itself reads the product context and never copies it in. Undeclared or `missing` → nothing.
- **Read order**: § Upgrade matches traces with `git grep -l`/`-n`, `git cat-file -e` and `git ls-tree`, printing no file; § Upgrade check ends "read `.flow.yml` alone, in a tool call of its own"; :120 names that step; :104 reads only the `stacks:` line; :42 and :47 apply after § Territories. Reads are not validated (`decisions-check` is V5).
